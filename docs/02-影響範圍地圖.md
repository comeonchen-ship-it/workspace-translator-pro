# 02 — 影響範圍地圖（改東西前必讀）

> **你問的「全域 or 非全域」，在軟體工程裡通常叫做「爆炸半徑（blast radius）」
> 或「耦合度 / 影響範圍（impact scope）」。**
>
> 這份文件把整個專案切成兩類：
> - 🔴 **共用（全域）**：改它會同時影響 Slides、Docs、Sheets、Forms 四種檔案，或所有引擎。
> - 🟢 **專屬（非全域）**：改它只影響一種檔案類型或一個引擎，其他功能不會被波及。
>
> **黃金原則：能在 🟢 區完成的需求，就絕對不要動 🔴 區。**

## 四、`chrome.storage.local` 的鍵值全覽

storage 是這個專案的「資料庫」。**這裡就是最典型的全域 vs 非全域對比。**

### 🔴 全域鍵（所有檔案、所有任務共用一份）

| Key | 型別 | 寫入者 | 說明 |
|---|---|---|---|
| `translationEngine` | string | popup.js | `gemini`/`openai`/`claude`/`custom`/`free` |
| `apiKey` | string | popup.js | ⚠️ **明文儲存** |
| `modelName` | string | popup.js | 模型名稱 |
| `customUrl` | string | popup.js | 自訂端點 base URL |
| `apiKeyStatus` | string | popup.js | `active`/`invalid`/`unverified`。**不是 `active` 就不給翻譯** |
| `lastSelectedLang` | string | popup.js | 新檔案的預設語言 |
| `activeTranslationIds` | string[] | background.js | 進行中的任務（上限 2） |
| `queuedTranslations` | object[] | background.js | 排隊中的任務（含完整 config） |
| `cancelledTasks` | string[] | 雙方 | 取消旗標。**注意：任務結束才會被清掉** |
| `tabMappings` | `{tabId: fileId}` | background.js | 分頁關閉時反查用 |
| `activeCopies` | `{fileId: {copyId, token}}` | background.js | ⚠️ 內含 OAuth token |
| `completedTranslations` | object[] | background.js | 歷史（上限 20，FIFO） |
| `debugLogs` | string[] | translate.js | 沒帶 fileId 時的後備日誌 |

### 🟡 半全域鍵（依引擎 × 語言切分）

| Key 樣板 | 說明 |
|---|---|
| `translationCache_{engine}_{lang}` | 翻譯快取。**刻意按引擎切開**，避免不同引擎的品質互相污染。上限 2000 筆，超過砍最舊 500 筆（[translate.js:246](../translate.js:246)） |

> 例：`translationCache_gemini_zh-TW`、`translationCache_claude_ja` 各自獨立。
> 這是很好的設計 —— 換引擎不會沿用舊引擎的譯文。

### 🟢 非全域鍵（每個檔案一份，互不干擾）

| Key 樣板 | 說明 |
|---|---|
| `taskState_{fileId}` | `{step, pct, status, error, finalUrl}`。關掉側邊欄再開還能看到進度 |
| `debugLogs_{fileId}` | 該檔案的日誌，上限 50 行（[translate.js:68](../translate.js:68)） |
| `targetLang_{fileId}` | 該檔案記住的目標語言。翻譯完成後也會替**新複本**寫一份（[background.js:352](../background.js:352)），所以切到譯本分頁時語言選項不會跳掉 |

### ⚠️ 改 storage key 名稱 = 破壞性變更

使用者的設定、歷史、快取全部靠 key 名稱找。改名等於：
- 設定全部回到預設（使用者要重新貼 API Key 並重新 Test Connection）
- 歷史紀錄全部消失
- 快取全部失效（下次翻譯要重新付費呼叫 API）

**若真的必須改名，必須寫資料遷移程式**（在 `chrome.runtime.onInstalled` 讀舊 key 寫新 key）。
目前專案**完全沒有遷移機制**。

### 💣 地雷 #3：`isTranslatable()` 是四種檔案的共同守門員

[background.js:803](../background.js:803)。它決定什麼字**不送**去翻譯：

```js
網址（http/https/www 開頭）  → 跳過（保護連結）
email                        → 跳過
純數字與數學/日期符號        → 跳過
單一非文字字元               → 跳過
```

放寬它 → 網址和 email 會被 LLM 改壞，超連結失效（這正是它存在的原因）。
收緊它 → 正常內容不會被翻譯，使用者以為功能壞了。

**改動前請務必用「含大量連結的簡報 + 含公式的試算表 + 含 email 的表單」三種檔案都測一遍。**

### 💣 地雷 #4：`replaceAllText` 的長度排序

[background.js:480](../background.js:480) 與 [499](../background.js:499)：

```js
const sortedTexts = uniqueTextsArray.sort((a, b) => b.length - a.length);
```

**由長到短排序是必要的，不是隨意寫的。** 如果反過來（短的先換）：

```
原文有「產品」和「產品說明書」兩個字串
若先處理「產品」→ 全文的「產品」都變成「Product」
→「產品說明書」變成「Product說明書」
→ 之後要換「產品說明書」時已經找不到了
```

**永遠不要移除或改變這個排序。**

### 💣 地雷 #5：Service Worker 的記憶體變數不可信

```js
let activePort = null;               // background.js:129
let activeViewPresentationId = null; // background.js:130
let apiLockPromise = ...;            // translate.js:17
let lastApiRequestTime = 0;          // translate.js:18
```

Service Worker 被 Chrome 殺掉時這些**全部歸零**。
- 不要在這些變數裡放「必須存活」的資料。
- 需要跨重啟存活的東西 → 一律寫 `chrome.storage.local`。
- 新增全域狀態時請自問：「SW 重啟後這個值歸零，會出什麼事？」

### 💣 地雷 #6：程式碼裡的中文字串，有一半**不是**介面文字，刪掉會壞功能

**本產品是英文版介面。** 介面文字已於 2026-08-04 全面英文化，
但 `popup.js` 裡仍刻意保留了一批中文字串 —— 它們是**比對用的樣板，不是顯示給使用者的文字**。

若有人日後做「移除所有中文」的全域搜尋取代，**一定會誤刪這些並造成功能故障**：

| 位置 | 內容 | 用途 | 刪掉的後果 |
|---|---|---|---|
| [popup.js:582-585](../popup.js:582) | `" - Google 文件"`、`" - Google 簡報"`、`" - Google 試算表"`、`" - Google 表單"` | 從 Chrome 分頁標題**移除**的後綴。Google 帳號語言設為中文時，分頁標題就是這些字 | 側邊欄標題會顯示「我的文件 - Google 文件」而不是「我的文件」，譯本檔名也會跟著髒掉 |
| [popup.js:598-600](../popup.js:598) | `管理員警告`、`存取遭拒`、`未经验证` | 髒標題過濾（Tier 1 子字串比對） | 權限錯誤頁的標題會被誤認成檔名 |
| [popup.js:606-608](../popup.js:606) | `登入`、`錯誤`、`載入中` | 髒標題過濾（Tier 2 完全相等比對） | 頁面載入中的暫時標題會被誤認成檔名 |
| [popup.html:74-78](../popup.html:74) | `繁體中文`、`简体中文`、`日本語`、`한국어` | 語言選單的**原生語言名稱** | 使用者要找日文時看不到「日本語」，可用性下降（Google／Apple／Microsoft 的語言選單都保留原生名稱） |
| [background.js:331-335](../background.js:331) | `LANG_LABELS` 的原生語言名 | 譯本**檔名**：`[Translated - 日本語] xxx` | 檔名變成 `[Translated - ja]`（若連 key 一起刪）。這是輸出而非介面，目前刻意保留 |

**判斷原則**：
- 中文字串出現在 `textContent` / `innerHTML` / HTML 文字節點 → **是介面文字，必須英文**
- 中文字串出現在陣列、比對清單、`includes()` / `replace()` 的參數 → **是比對樣板，必須保留**

## 六、依賴方向圖（單向，請維持）

```
manifest.json
    │ 宣告進入點
    ├──────────────► background.js (service worker)
    │                     │ import
    │                     └──► translate.js
    │                              │
    │                              └──► （不 import 任何東西）
    │
    ├──────────────► popup.html ──► popup.js ──► popup.css
    │                                   │
    │                                   └── 透過 port 與 background.js 通訊
    │                                       （不 import，用訊息）
    │
    └──────────────► onboarding.html ──► onboarding.js ──► onboarding.css
                                             （完全獨立，不與翻譯功能耦合）
```

**必須維持的規則：**

1. `translate.js` **不 import 任何東西**（除了用 `chrome.storage` 與 `fetch` 全域 API）。
   它是最底層，保持它對 Google Workspace 無知。
2. `popup.js` **不 import** `background.js` 或 `translate.js`。
   它們在不同執行環境，只能透過訊息通訊。
3. 依賴方向永遠是 `background.js → translate.js`，**絕不反向**。
   若你發現需要在 translate.js 呼叫 background.js 的函式 → 設計出錯了，
   應該把那個值當參數傳進來（現在的 `config` 物件就是這個用途）。

## 七、動手前的自檢清單

改任何程式碼之前，回答這七個問題：

- [ ] **1.** 我要改的函式，在第二節（🔴 共用區）的表格裡嗎？
      → 在 → 停下來，先想有沒有辦法改在 🟢 專屬區。
- [ ] **2.** 我改的東西被幾個地方呼叫？
      → 執行 `grep -n "函式名稱" *.js` 親自確認，不要憑印象。
- [ ] **3.** 我有動到 `chrome.storage` 的 key 名稱或資料結構嗎？
      → 有 → 需要資料遷移計畫，這是破壞性變更。
- [ ] **4.** 我有動到語言清單或 prompt 嗎？
      → 有 → 檢查地雷 #1（三處）與地雷 #2（四處）是否都同步了。
- [ ] **5.** 我有動到 `manifest.json` 的 `key`、`permissions`、`host_permissions` 嗎？
      → 有 → 這會影響上架審查與既有使用者，需要明確決策。
- [ ] **6.** 我新增的記憶體變數，在 Service Worker 重啟後歸零會怎樣？
      → 會出錯 → 改用 `chrome.storage.local`。
- [ ] **7.** 我打算跑哪些測試？
      → 見 [03-修改指南](03-修改指南.md) 的分級測試清單。
      **動到 🔴 共用區，四種檔案類型全部都要測。**
