## 2. 分層責任（為什麼這樣切）

這個專案只有三層，界線切得相當乾淨，**維護時請守住這條界線**：

| 層 | 檔案 | 只負責 | 絕對不該做 |
|---|---|---|---|
| **表現層** | popup.js / popup.html / popup.css | 偵測分頁、收集設定、顯示進度、歷史清單 | 不呼叫 Google API、不做翻譯 |
| **協調層** | background.js | 認證、複製檔案、抽取文字、寫回文字、佇列 | 不直接組 LLM 的 HTTP 請求 |
| **引擎層** | translate.js | 把「一堆字串」變成「一堆翻譯」 | 不知道 Slides/Docs/Sheets/Forms 的存在 |

**translate.js 對 Google Workspace 完全無知**——它的介面就只有
`translateTexts(texts: string[], targetLang: string, config) → Map<原文, 譯文>`。
這是整個專案最好的設計決定，請不要破壞它（不要在 translate.js 裡塞任何 Slides/Docs 專屬邏輯）。

唯一的例外：`config.presentationId` 被傳進 translate.js，只用於「寫日誌」和「檢查是否被取消」。

## 3. 一次翻譯的完整資料流（14 步）

以「翻譯一份 Google Slides 成越南文」為例，逐步對照原始碼：

| # | 發生什麼 | 位置 |
|---|---|---|
| 1 | 使用者切到 Google Slides 分頁。`handleTabChange()` 用正規表示式從網址抓出檔案 ID，判斷 `fileType = 'presentation'`，更新側邊欄標題與圖示 | [popup.js:510](../popup.js:510) |
| 2 | 使用者按 Start Translation。先檢查 `apiKey` 存在且 `apiKeyStatus === 'active'`，否則彈警告視窗 | [popup.js:812](../popup.js:812) |
| 3 | 透過 port 送出 `startTranslation`，把 `presentationId / title / fileType / targetLang / tabId / config` 一起帶過去 | [popup.js:852](../popup.js:852) |
| 4 | 背景收到訊息。`registerTabMapping()` 記住「這個 tabId 對應這個檔案」（分頁關掉時要用來取消任務） | [background.js:164](../background.js:164) |
| 5 | `requestTranslationStart()` 檢查併發額度。`MAX_CONCURRENT_TRANSLATIONS = 5`；額滿則進 `queuedTranslations` 佇列並回報「Waiting in queue #N」 | [background.js](../background.js) |
| 6 | `triggerTranslation()` 建立 `sendProgress` 回呼（同時寫 storage + 推送給側邊欄），呼叫 `runTranslationWorkflow()` | [background.js:1684](../background.js:1684) |
| 7 | **進度 10%** `getAuthToken()` 取 Google OAuth token。先靜默嘗試，失敗才彈登入視窗 | [background.js:602](../background.js:602) |
| 8 | **進度 25%** `duplicateGoogleFile()` 用 Drive API v3 複製檔案。先查原檔的 `parents` 讓複本落在同一資料夾。取得 `copyId` | [background.js:820](../background.js:820) |
| 9 | 依 `fileType` 分岔。Sheets 走 `translateSpreadsheet()`、Forms 走 `translateForm()`（兩者自成一條完整支線並提早 return）；Docs / Slides 繼續往下 | [background.js:354](../background.js:354) |
| 10 | **進度 40%** 抓複本結構（Slides API `presentations.get`），遞迴走訪 `pageElements`，把可翻譯文字收進 `uniqueTexts: Set` 與 `pageTextMap: Map<pageId, Set<text>>` | [background.js:725](../background.js:725) |
| 11 | **進度 60%** `translateTexts()`。查快取 → 動態分批 → 逐批循序送 LLM → 寫回快取 | [translate.js:82](../translate.js:82) |
| 12 | **進度 80%** 產生 `replaceAllText` 請求。**依字串長度由長到短排序**（避免短字串先被換掉、破壞長字串的比對），Slides 額外帶 `pageObjectIds` 限定頁面 | [background.js:473](../background.js:473) |
| 13 | 一次 `batchUpdate` 全部寫回複本 | [background.js:700](../background.js:700) |
| 14 | **進度 100%** `saveToHistory()` 寫入歷史（上限 20 筆），`chrome.tabs.create()` 開啟譯本，`onTranslationFinished()` 釋放併發槽並拉下一個佇列任務 | [background.js:1634](../background.js:1634) |

### 進度階段對照表

側邊欄的四顆步驟燈與 `step` 字串一對一對應（[popup.js:1076](../popup.js:1076)）：

| `step` | 百分比 | 側邊欄顯示 |
|---|---|---|
| `queue` | 0 | 排隊中 |
| `copy` | 10 → 25 | Duplicate original |
| `extract` | 40 | Extract elements & text |
| `translate` | 60 | Translate via API |
| `write` | 80 → 90 | Apply translations |
| `done` | 100 | 全綠，3 秒後自動收起 |
| `error` | 0 | 紅字 + 自動展開 Log Console |

## 4. 四種檔案類型的處理策略（差異很大，務必分清）

這是整個專案最需要理解的部分。四種檔案**寫回的機制完全不同**：

### Slides（簡報）— `replaceAllText` + 頁面隔離
- 讀：`slides.googleapis.com/v1/presentations/{id}`
- 抽取：遞迴走訪 shape / table / group，另外也處理**演講者備忘稿**（`slideProperties.notesPage`）
- 寫：`replaceAllText`，並帶 `pageObjectIds: [pageId]`
- **為什麼要按頁隔離**：同一句話在不同頁可能該有不同譯法；也降低誤替換範圍
- 版面保留：靠 Google 自己的「原地換字」，樣式不動

### Docs（文件）— `replaceAllText` + 表格內距微調
- 讀：`docs.googleapis.com/v1/documents/{id}`
- 抽取：走訪 `body.content`，**外加 headers / footers / footnotes / tableOfContents**
- 寫：`replaceAllText`（全文件範圍，無法按頁隔離）
- 額外步驟：翻譯後**另外**送一批 `updateTableCellStyle` 把表格內距縮小（3pt/5pt），
  避免譯文變長撐破表格。這步包在 try/catch 裡，**失敗不影響翻譯結果**（[background.js:558](../background.js:558)）

### Sheets（試算表）— 逐格 `updateCells`
和前兩者完全不同，因為 Sheets 沒有 `replaceAllText`：
- 讀：`includeGridData=true`，並用 `fields` 參數只取 `userEnteredValue, textFormatRuns, formattedValue, hyperlink`
- 抽取三種東西：儲存格純文字、**工作表分頁名稱**、`=HYPERLINK("url","標籤")` 公式裡的標籤
- 寫：**每一格產生一個 `updateCells` 請求**（逐格精準寫入）
- 格式保留的巧思（[background.js:1093](../background.js:1093)）：
  - 儲存格內的 `textFormatRuns`（局部粗體、局部超連結）會**按比例縮放** `startIndex`
    到新譯文的長度，超出範圍的 run 直接丟掉
  - 若整格是超連結（`cell.hyperlink`）但沒有 format run，就補一個 `startIndex: 0` 的 link run
  - `=HYPERLINK()` 公式只換標籤，**網址原封不動**
- 收尾：翻譯分頁名稱 + `autoResizeDimensions` 自動調整所有欄寬

### Forms（表單）— 整個 item 讀出來改完寫回
- 讀：`forms.googleapis.com/v1/forms/{id}`
- 抽取：表單標題／說明、**送出後的確認訊息**、每題標題／說明、選擇題選項、
  量表的高低標籤、方格題的列標題與欄選項、**測驗的正確答案**
- 寫：對每個有變動的 item 做 `updateItem`，深拷貝整個 item 改完塞回去，
  `updateMask` 依 item 型態動態組合
- 兩個踩過的坑（程式碼註解有寫）：
  1. **複製 Form 時不能在 body 帶 `mimeType`**，否則 Drive API 回 400
     （Forms 是原生格式，不支援格式轉換參數）—— [background.js:850](../background.js:850)
  2. **圖片欄位要把唯讀的 `contentUri` 改名成可寫的 `sourceUri`**，
     否則 Forms API 驗證失敗 400；沒有 `sourceUri` 就整個 `image` 欄位刪掉 —— [background.js:1504](../background.js:1504)

## 5. 翻譯引擎層設計（translate.js）

`translateTexts()` 的五個階段：

```
輸入: string[]（已去重）
  ↓
① 讀快取  key = translationCache_{engine}_{lang}
   ↓ 全部命中 → 直接 return（0 次 API 呼叫）
② 分批    依「字元數」與「筆數」雙上限切批
③ 循序送  一批一批送，絕不並行（見下方說明）
④ 寫快取  上限 2000 筆，超過就 FIFO 砍掉最舊 500 筆
⑤ return Map<原文, 譯文>
```

### 各引擎的分批與冷卻參數（[translate.js:147](../translate.js:147)）

| 引擎 | 每批字元上限 | 每批筆數上限 | 請求間冷卻 | 預設模型 |
|---|---|---|---|---|
| `gemini` | 4000 | 35 | 4200 ms | `gemini-3.1-flash-lite` |
| `openai` | 6000 | 50 | 2000 ms | `gpt-5.4-mini` |
| `claude` | 5000 | 50 | 2000 ms | `claude-haiku-4-5-20251001` |
| `custom` | 8000 | 60 | 1000 ms | 使用者填 |
| `free` | 不分批，5 筆並行 | — | 100 ms | — |

> `gemini` 的 4200ms 冷卻是刻意算過的：60000 / 4200 ≈ 14.3 RPM，
> 壓在 Gemini 免費層 15 RPM 之下。

### 三層防護：Mutex → 冷卻 → 指數退避

1. **全域互斥鎖** `acquireApiLock()`（[translate.js:20](../translate.js:20)）
   用一條 promise chain 串起所有請求，保證同一時間只有一個請求在排隊檢查。
2. **冷卻間隔** 距上次請求不足 `cooldownMs` 就等待，而且等待期間**每 200ms 檢查一次使用者是否按取消**。
3. **指數退避重試** `fetchWithRetryAndTimeout()`（[translate.js:264](../translate.js:264)）
   遇 429 / 5xx / 逾時 / 網路錯誤，`6000 × 2^attempt + 隨機 0~1000ms`，最多重試 5 次。

**注意**：批次是**循序**處理的（[translate.js:197](../translate.js:197) 的註解說明了原因）——
若並行，多個 429 重試會互相搶鎖，反而更慢更容易失敗。

### LLM 回應的容錯解析

LLM 常常不乖乖只回 JSON。`parseJsonRobustly()`（[translate.js:422](../translate.js:422)）三段式救援：

1. 直接 `JSON.parse`
2. 剝掉 markdown ```json 圍欄再試
3. `extractJsonBlock()` 用「括號配對 + 字串狀態機」把第一個完整 JSON 區塊挖出來
   （會正確跳過字串內的括號和轉義字元）

Claude 額外用了 **prefill 技巧**（[translate.js:569](../translate.js:569)）：
先在 assistant 訊息塞 `{\n  "translations": [`，強迫它從 JSON 中間開始接，
解析時再把 prefill 接回去。

### 統一的 System Prompt

四個 LLM 引擎共用同一段 prompt（**但是被複製了四份**，見 [05-已知問題](05-已知問題與技術債.md)）：
要求「回傳 `{"translations": [...]}`、順序長度完全一致、保留語氣與排版佔位、**不要動 URL 和 email**」。

## 6. 認證機制

**沒有**使用 manifest 的 `oauth2` 欄位 + `chrome.identity.getAuthToken()`，
而是自己走 `chrome.identity.launchWebAuthFlow()`（[background.js:602](../background.js:602)）：

- Client ID **內建在程式碼裡**（`BUNDLED_CLIENT_ID`，[background.js:4](../background.js:4)），使用者不用自己申請
- `response_type=token`（Implicit Flow）→ **只拿到 access token，沒有 refresh token**
- 五個 scope：`presentations` `documents` `spreadsheets` `forms.body` `drive`
- 策略：先 `interactive: false` 靜默嘗試；失敗才 `interactive: true` 彈視窗

**Extension ID 鎖定**：manifest 的 `key` 欄位（公鑰）讓擴充功能在開發模式與上架版本
擁有**同一個 ID**，因此 OAuth redirect URI (`https://{id}.chromiumapp.org/`) 保持不變。
這是 v1.3.0 的主要改動之一。對應的私鑰是 `key.pem` —— 見 [04-版本與發布](04-版本與發布.md)。

## 7. 通訊機制

### 長連線 Port（雙向、即時）
`popup.js` ↔ `background.js`，port 名稱 `'translation-channel'`

| 方向 | `action` / `type` | 用途 |
|---|---|---|
| UI → 背景 | `registerView` | 告訴背景「我現在在看哪個檔案」，背景會立刻回推該檔案的既有狀態 |
| UI → 背景 | `startTranslation` | 開始翻譯 |
| UI → 背景 | `cancelTranslation` | 把 ID 加進 `cancelledTasks` |
| UI → 背景 | `ping` | 每 10 秒一次，撐住 Service Worker |
| 背景 → UI | `translationProgress` | 推送 `{step, pct, status, error, finalUrl}` |
| 背景 → UI | `pong` | 回應 ping |

Port 斷線會**自動重連**（1 秒後重試，[popup.js:470](../popup.js:470)）。

### 一次性訊息（`chrome.runtime.sendMessage`）

| `action` | 方向 | 用途 |
|---|---|---|
| `settingsUpdated` | UI → 背景 | 純記日誌通知 |
| `syncHistoryFiles` | UI → 背景 | 對照 Drive 檢查歷史檔案是否已被刪除 |
| `historyUpdated` | 背景 → UI | 通知 UI 重新載入歷史清單 |

### 進度的「雙寫」設計

`sendProgress()` 每次都做兩件事（[background.js:1697](../background.js:1697)）：
1. `setTaskState()` 寫進 `chrome.storage.local`（**持久化，關掉側邊欄再打開還在**）
2. 透過 port 推給側邊欄（**即時**）

而且推送前會比對 `activeViewPresentationId === pid`——
**只推給正在看該檔案的側邊欄**，避免翻譯 A 檔案時 B 檔案的進度條亂動。

## 8. 取消機制（Cooperative Cancellation）

沒有用 `AbortController` 貫穿全流程，而是用**協作式檢查點**：

- 取消時把 ID 推進 `chrome.storage.local` 的 `cancelledTasks` 陣列
- 流程中散佈約 12 個 `checkCancelled()` / `checkCancelledGlobal()` 檢查點，
  一旦發現就 `throw new Error('Translation stopped by user.')`
- 連冷卻等待的迴圈裡都每 200ms 檢查一次（[translate.js:44](../translate.js:44)）
- **關鍵補償動作**：catch 區塊會檢查「這個任務是被取消的嗎」，
  若是就呼叫 `deleteGoogleFile()` 把已經複製出來的 Drive 檔案刪掉，
  不留垃圾檔（[background.js:580](../background.js:580)）

## 9. 併發與佇列

```
使用者連按 3 個檔案的翻譯
        ↓
activeTranslationIds = [A, B, C, D, E]  ← 上限 MAX_CONCURRENT_TRANSLATIONS = 5
queuedTranslations   = [F]              ← F 顯示「Waiting in queue #1」
        ↓ A 完成
onTranslationFinished(A)
  → activeTranslationIds 移除 A
  → 從佇列 shift 出 C，推進 active
  → 重新計算所有剩餘佇列任務的排隊號碼並推送給 UI
```

**分頁關閉的連動處理**（[background.js:1719](../background.js:1719)）：
`chrome.tabs.onRemoved` 觸發時，用 `tabMappings` 反查該分頁對應的檔案，
把它從佇列或 active 清單移除，刪掉 `taskState_`，並拉下一個佇列任務進來。

> ⚠️ 注意一個微妙之處：`MAX_CONCURRENT_TRANSLATIONS = 5` 指的是「同時進行的翻譯任務」，
> 但 `acquireApiLock()` 是**全域**的——所以這 5 個任務的 LLM 請求仍然會排隊序列化。
> 併發帶來的好處主要在「檔案複製、結構讀取、寫回」這些 Google API 階段。
> 因此把上限調高**不會**成比例加速（LLM 那步仍輪流），也**不會**放大 LLM 的限流壓力。

## 10. UI 設計

- **側邊欄而非彈出視窗**：`manifest.json` 用 `side_panel`，且
  `setPanelBehavior({ openPanelOnActionClick: true })`。好處是切分頁時面板不會消失，
  長時間翻譯可以一直看進度。
- **三個疊層面板**：`main-panel` / `settings-panel` / `history-panel`，用 `.active` class 切換
- **依檔案類型換色**：`document.body.className = 'theme-{fileType}'`，
  CSS 在 [popup.css:898](../popup.css:898) 定義四組色票（簡報黃、文件藍、試算表綠、表單紫）
- **錯誤訊息本地化**：`translateErrorToHuman()`（[popup.js](../popup.js)）
  把 429 / 403 / 400 / 逾時 / 中斷 / 使用者取消等原始錯誤，對應到 `error.*` 的 i18n 鍵，
  附帶具體解決建議，**跟隨使用者選的介面語言顯示**（不再是寫死的中英雙語）
- **可切換介面語系（10 種）**：執行期 i18n 系統，`data-i18n` 屬性 + `t()` 動態填字，
  語言註冊表在 `i18n/languages.js`。切換語言不重載頁面。完整設計見
  [06-多語系介面設計](06-多語系介面設計.md)
- **標題髒資料過濾**（[popup.js:594](../popup.js:594)）：分頁標題可能暫時是
  「管理員警告」「登入」「Loading…」等，用兩層規則過濾：
  - Tier 1 特定片語 → 子字串比對（這些片語不會出現在真實檔名裡）
  - Tier 2 短常見詞（`Error`/`登入`）→ **只有完全相等才擋**（避免誤擋「Error Report」這種真檔名）
- **翻譯完成後鎖定 15 秒**：`tabChangeLocked`（[popup.js:1113](../popup.js:1113)），
  防止新開的譯本分頁把 UI 標題搶走
